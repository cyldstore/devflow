Vue 3 响应式：ref 与 reactive 的边界

更新于今天 14:323 次学习下次复习 3 天后 在学
阅读 编辑
专注 25:00

面试里更容易失分的，不是 API 怎么用，而是你说不清什么时候不该用它。

01 一句话回答

ref 通过 getter/setter 追踪单个值的读写，reactive 通过 Proxy 代理整个对象。基本类型用 ref，需要整体替换或解构时也要谨慎。

02 我的答案

  • ref 适合基本类型和需要保持引用的场景，模板中自动解包，脚本里要写 .value。
  • reactive 只对对象生效，解构会丢失响应性；需要解构时用 toRefs。
  • 从组合式函数返回状态时，优先返回 ref，调用方不需要关心响应式实现。
TSconst state = reactive({ count: 0 })
const count = ref(0)

watchEffect(() => {
  console.log(state.count, count.value)
})
面试表达：先讲使用边界，再讲实现机制，最后补一个真实踩坑。比背源码更有说服力。

03 常见追问

  • 为什么 reactive 解构后会失去响应性？
  • shallowRef 适合什么场景？和 ref 的更新触发有什么区别？
